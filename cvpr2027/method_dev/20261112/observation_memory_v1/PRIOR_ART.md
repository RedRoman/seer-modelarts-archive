# Observation memory: prior art and source-only screen

This is a lab note for a new module pilot, not a manuscript or a novelty claim. The hypothesis is that frozen VJEPA features can provide useful cross-frame addresses for retrieving **actual calibrated low-light observations**. The value stream carries observed high-frequency blocks; a small residual predictor consumes the retrieved values. Addressing, values and a memory factorization must be tested separately.

## Closest primary sources

| Source | Existing mechanism | Boundary for this pilot |
| --- | --- | --- |
| [TTSR, CVPR 2020](https://openaccess.thecvf.com/content_CVPR_2020/html/Yang_Learning_Texture_Transformer_Network_for_Image_Super-Resolution_CVPR_2020_paper.html) | Matches queries and keys extracted from degraded target/reference images, then transfers values from the original reference. Its equations use `Q=LTE(LR↑)`, `K=LTE(Ref↓↑)`, `V=LTE(Ref)`. | Separating correspondence features from a detailed observed value stream is established. Here the proposed address source is a frozen video representation and the values are noisy observations from the same clip. That difference requires evidence; it does not establish novelty by itself. |
| [Efficient Attention, WACV 2021](https://arxiv.org/pdf/1812.01243), [official code](https://github.com/cmsflash/efficient-attention) | Equations 3–4 aggregate values into global contexts using normalized keys, then combine those contexts using normalized queries: `softmax_row(Q)[softmax_col(K)^T V]`. | A write/read implementation with this formula is the existing dual-normalization attention operator. Calling its intermediate tensor a slot memory is an interpretation. It is exactly equivalent to the corresponding dot-product operator under scaling normalization; two separately normalized softmax factors are **not** exactly `softmax(QK^T)`. |
| [Memory-Augmented Non-Local Attention for Video Super-Resolution, CVPR 2022](https://arxiv.org/html/2108.11048) | Combines cross-frame nonlocal retrieval with a learned global detail memory. The described cross-frame search uses a 9×9 neighborhood and one-hot value selection; its external memory is learned during training. | Cross-frame retrieval, residual detail recovery and memory augmentation are established. A clip-specific memory written from current observed values differs from its learned external dictionary, but that alone is insufficient as a contribution. |
| [SPIN, ICCV 2023](https://openaccess.thecvf.com/content/ICCV2023/html/Zhang_Lightweight_Image_Super-Resolution_with_Superpixel_Token_Interaction_ICCV_2023_paper.html) | Groups similar pixels into superpixels and propagates information through superpixel token interactions and cross-attention. | Compressed pixel→token→pixel propagation is established. A small set of shared addresses is not a new principle by itself. |

These sources do not establish that the particular frozen-VJEPA/observed-value combination has been published, and this short check is not an exhaustive novelty search. They do establish that nonlocal retrieval, address/value separation and factorized memory cannot be presented as first principles introduced here.

## Falsifiable distinction from the earlier local fusion

The proposed claim is narrower: given the same observed values and restoration budget, frozen video features may supply better cross-frame addresses than ordinary pixel features, and the retrieved other-frame observations may add useful detail beyond local fusion.

- Keep the calibrated observation recipe, value blocks, residual decoder, loss, fit scenes and sample plan matched between `prior_cross` and `pixel_cross`. Record any parameter or computation differences instead of attributing them to the address source.
- `shuffled_cross` tests address/value correspondence, `prior_same` tests the value source, and `pixel_local` provides a local reference. The current shuffle permutes frame-spatial address locations, while values remain fixed; same-frame mode writes and reads the target frame. Local mode reads the same spatial patch in valid adjacent frames and is not an ordinary full nonlocal-attention benchmark.
- Exclude a target frame's own value writes from its other-frame retrieval, including the relevant normalization. Frozen VJEPA addresses can still depend on the whole clip and on temporally pooled tokens; excluding a value does not remove this contextual dependence. The frozen base prediction is also an all-clip output.
- Preserve within-block high-frequency phase. Averaging signed high-frequency RGB into a single value can cancel the detail that the module is meant to transport. Any block embedding must be identical across matched address controls.
- Improvement over the base alone does not establish the mechanism. A convincing result also needs a benefit over pixel addressing and the strong frozen local reference, plus degradation under a control that destroys the relevant cross-frame correspondence. A shuffle effect by itself can reflect a distribution change and is not sufficient proof.

## Frozen first source screen

The first screen contains exactly five modes: `prior_cross`, `pixel_cross`, `shuffled_cross`, `prior_same`, and `pixel_local`. Each uses seed0, a fixed 400-step budget, crop128, patch16, and eight supervised frames. No intermediate target evaluation or target-dependent choice is permitted. Fit-only statistics determine dataset-level normalization; observable per-clip centering and low/base gain calibration are fixed input operations and do not use GT.

Reuse the existing source scene split from seed20261114: 136 SDSD training clips grouped into 68 scenes, with 51 fit scenes and 17 internal development scenes. The fit set contains 15 indoor and 36 outdoor scenes; the internal set contains eight indoor and nine outdoor scenes. Keep each scene's original and `_2` clips together. The frozen base may have seen these internal scenes during its own training, so this is a module development split, not an independent generalization test.

After final400, evaluate the complete 34 internal clips once at full256 and all16 frames. The primary development score is RGB MSE aggregated by scene; retain both clips per scene and report indoor/outdoor breakdowns. Any scene bootstrap interval is conditional on this single fitted head and base, exploratory, and unadjusted for the five-mode screen. It is not evidence from independent base-training repetitions.

The root-defined development gate is at least +0.05dB mean clip-PSNR against both `pixel_cross` and the frozen base, with the 95% scene-bootstrap upper endpoint of the MSE difference versus `pixel_cross` below zero (10,000 draws, RNG0). The fixed, strong v2 `raw_node_s0` is also a reference: the proposed module must improve its mean scene MSE before investing in a target evaluation. It must also beat `prior_same` and `shuffled_cross` on mean scene MSE. The frozen v2 head trained for 1,000 steps and has a different architecture and budget, so it is a practical strong reference rather than an isolated ablation. These are development decisions, not a SOTA threshold or confirmatory statistical claim. Report every screened mode and the gate outcome, including a failure.

Only if that gate passes, add an ordinary nonlocal/source-only control at matched budget and confirm the selected design with additional seeds or a source validation split that was not used for this screen. Lock the resulting design before any new BVI evaluation. Previous BVI results have already informed project development, so later results must retain the historical non-target-blind boundary even when this particular screen reads no target data.
