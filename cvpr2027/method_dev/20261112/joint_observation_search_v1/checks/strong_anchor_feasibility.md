# Frozen HVI spatial anchor: feasibility audit

Read-only design audit, 2026-11-12. No new model inference, source/target score,
RGB cache or GT cache was produced. The running joint-search screen, its Seer
anchor, protocol and costs remain frozen.

**Decision:** a frozen HVI anchor is technically feasible and is a stronger
practical starting point for a separate next phase. It is not a drop-in change
to the current manifest or frozen selector. No temporal-module gain is assumed.

## Evidence and interface

- The completed historical-checkpoint replay reports HVI PSNR-Y
  **24.241232037953157**, RGB **23.383146282739105**, LPIPS
  **0.15314976987428963** and absolute tLP gap **0.034284843131899834** on the
  common BVI VAL16/c256 protocol. The approximately 19.38 Y Seer result motivates
  reviewing the anchor; it does not establish any HVI-plus-module performance.
  These uint8 target metrics differ from source-screen float RGB PSNR.
- The actual release is
  `/cache/zihaohe/seer_baseline_replay_20261112/release_v1` on host 31051;
  `upstream/hvi_cidnet/net/CIDNet.py` defines `CIDNet()` with defaults
  channels `[36,36,72,144]`, heads `[1,2,4,8]`. Its `forward(x)` accepts RGB
  `[BT,3,H,W]` and returns RGB with the same shape; a video adapter only needs
  flatten/unflatten of batch/time, required-multiple16 padding, and final clamp.
- Reuse strict loading, float32, `eval()` and `requires_grad_(False)` from
  `baseline_replay_v1/run_replay.py:load_model`. The replay used batch1 and NPU
  float32, 191 state keys, with unchanged state. A future source cache should
  retain float predictions; the existing `forward_frames` returns rounded
  uint8 and is therefore not the correct training-cache interface. Quantize
  once, only when the declared target evaluator requires it.
- Existing weight:
  `/temp/zihaohe/seer_cvpr/baseline_ckpts/HVI-CIDNet/weights/generalization.pth`;
  release copy `weights/hvi_cidnet.pt`; 7,971,462 bytes;
  SHA256 `6395370762ec1fa0f6fe92a38c62382b1ebe21edc012f597023bfcec8b95cd27`.
  No existing SDSD136 HVI float-output cache was found in the inspected
  `/cache/zihaohe/seer*` runtimes; the baseline replay stored scores and hashes,
  not RGB predictions. Do not label the present source cache as HVI.

## Preserving the strong anchor and measurement constraints

With HVI base `B`, the current observable construction becomes
`g=clip(LP9(B)/(LP9(LQ)+1e-4),0.25,16)` and
`q=clip(LP9(B)+g*HP9(LQ),0,1)`. Each donor is warped as q **before** HP9;
candidate values use `clip(LP9(B_target)+HP9(warp(q_donor)),0,1)`.
This fixes most low-frequency appearance to HVI but replaces its high-frequency
content with amplified raw observations. Consequently:

- A stronger denoised anchor can leave less useful recoverable raw detail.
  Gain-squared noise amplification, gain saturation, q clipping and final RGB
  clipping can all change candidate quality. Source FIT diagnostics should
  record these rates and high-frequency residual energy; no improvement is
  implied by greater raw-detail amplitude. LP9 is a box filter rather than an
  orthogonal projection: adding HP9 and clamping does not exactly preserve the
  filtered HVI appearance. Only the explicit zero gate guarantees exact HVI.
- FIT calibration of `HP9(q)-HP9(GT)` estimates effective observation error,
  including bias and clipping; it is not physical camera noise or a guarantee
  that donor errors are independent. Fit coefficients and constant variance
  must be frozen before the new development evaluation.
- Validity remains original-mask intersect new geometric validity followed by
  HP9 support erosion. SSD must use common real supported pixels. Retaining old
  masks does not add an occlusion-confidence or forward/backward-flow guarantee.
- An unchanged HVI output must be an exact reachable default. In the current
  joint module, zero search amplitude returns **the frozen raw selector at
  original flows**, not the unmodified spatial base. Directly inserting HVI
  would therefore not establish HVI parity. The next module must separately
  enforce `gate=0 -> prediction=B_HVI`, with a FIT-only numerical parity check;
  correspondence refinement and permission to inject detail are separate.
- A matched HVI-donor-detail control can test whether raw observation values
  help beyond already denoised HVI donors. Any such control and training budget
  must be declared before new development scores, not added after selecting a
  favorable metric. Preserve low-frequency appearance only as the declared
  mechanism; it cannot repair a remaining exposure/color error by itself.

## Training provenance and fair claims

The original Seer checkpoint is `e17_small_pretrained_s0`, final20k, seed0,
SHA256 `5ab6b6d04d7b13743965007d3754bd66f034d170ec7193abc2abb5a8aa6c8740`.
Saved arguments and `tools/seer_train_cvpr.py` identify a from-scratch small
Restormer-style pixel branch, frozen pretrained V-JEPA taps5/11/17/23, LIC,
temporal mixer/CFIM, and pixel plus Retinex/smoothness objectives; no exposure
head. Saved learning rate is2e-5, accumulation8, crop256/clip16. The source-cache
provenance explicitly does **not** reconstruct a missing historical training
split hash, so this audit must not strengthen that claim.

The authors' [HVI README](https://github.com/Fediory/HVI-CIDNet) describes the
`LOLv2_syn/generalization.pth` model as trained on LOLv2-Syn with random gamma.
The saved README/URL/hash are in
`baseline_replay_v1/evidence/hvi_training_readme*`. The present local weight is
traceable to an existing shared-disk file, **without an original download
receipt or a fresh byte comparison against a public checkpoint**. Thus source
training identity is documented by author naming, not independently proven
from training logs or weight bytes; target-domain overlap cannot be certified
from the README alone.

For a future HVI anchor, compare unchanged HVI, matched pixel/shuffled-prior
controls and the proposed temporal module with the **same frozen HVI weights,
same source FIT labels and same budgets**. Report it as an SDSD-trained temporal
adapter on an externally pretrained spatial anchor. Do not call the complete
pipeline SDSD-only training. Reused Seer-flow proposals must be disclosed; they
also prevent interpreting a pixel-address arm as a globally V-JEPA-free system.

The HVI choice is informed by already seen BVI VAL results. A later repeat on
that VAL is development evidence, not a newly blind cross-domain test. Any
prospective untouched target evaluation needs its own frozen protocol and the
same training-information accounting. No new evaluation is performed here.
